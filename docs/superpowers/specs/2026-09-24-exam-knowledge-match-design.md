# 考试题知识点匹配 Demo 设计

## 目标

构建一个本地网页 Demo。用户输入一道考试题和若干个临时知识点，Laya 分别判断题目是否涉及每个知识点。结果允许一道题匹配多个知识点，并显示逐项概率、阈值判定和 Laya 原始结构化 JSON。

## 用户流程

1. 用户在题目文本框输入完整题目内容。
2. 用户在多行知识点输入框中每行填写一个知识点。
3. 用户点击“开始匹配”。
4. 页面显示每个知识点的匹配概率和匹配状态，并提供原始 JSON 展示区。
5. 用户拖动匹配阈值滑块，页面立即更新匹配状态，不重新调用模型。

输入校验要求题目非空，且至少提供一个非空知识点。去除每行首尾空格，忽略空行，并保留用户输入顺序。

## 匹配语义与模型调用

每个知识点对应一个独立的 Laya `noul` 判断问题。判断语义为：“解答这道题是否需要运用该知识点？”仅在题目中提到某术语、但解题并不依赖它时，不应判为匹配。

后端把题目作为共享 state，把每个知识点作为一个具名问题，通过一次 `Router.predict()` 请求提交。问题键使用稳定的序号标识（例如 `kp_1`、`kp_2`），展示时再映射回用户输入的知识点文本。读取每项 `noul` 的 true 概率作为匹配概率；同一题可有任意多个知识点超过阈值。

模型路由默认使用 `multilingual`，以适配中文输入；采用懒加载，首次匹配时才下载并载入所需模型。网页服务使用项目已选择的 `laya[serve]` 依赖和 FastAPI。

## 页面与结果

- 题目多行文本框。
- 知识点多行文本框，每行一个知识点。
- 0%–100% 阈值滑块，步长 1%，默认 60%，显示当前数值。
- 匹配结果列表：知识点文本、概率百分比、概率条，以及“匹配”或“不匹配”状态。
- 可展开的 JSON 区域，展示未经页面重组的完整 Laya 返回对象。

匹配规则为 `概率 >= 阈值`。阈值只控制页面上的分类，不影响 Laya 概率，也不触发新的模型推理。原始 JSON 保留模型结果，包括路由信息和答案字段。

## 组件与接口

- FastAPI 应用负责提供网页、接收匹配请求并调用 Laya。
- 浏览器页面负责收集输入、提交请求、渲染结果和本地重算阈值分类。
- `POST /api/match` 接收 `question` 字符串及 `knowledge_points` 字符串数组，成功时返回原始 Laya 结果和逐项知识点键值映射。匹配概率读取 `answers[kp_key].noul`。
- 页面不得自行推断或改写原始 Laya JSON；独立的可视化结果可由已返回的 `answers` 生成。

## 错误处理

- 缺少题目或有效知识点时，在页面提示并避免发送请求。
- 模型首次下载或推理失败时，页面显示简明错误信息，保留用户已输入内容，并允许重试。
- 服务端验证请求字段和非空知识点，避免因手工构造请求绕过页面校验。

## 验收标准

1. 可以提交一道题和多个临时知识点，并逐项看到概率。
2. 多个知识点可以同时显示为匹配。
3. 改变阈值后分类即时更新，期间没有新的模型请求。
4. JSON 区域能够展示该次调用完整的原始 Laya 返回对象。
5. 中文输入时使用 multilingual 默认路由，模型按需加载。

## 范围

本 Demo 仅实现单题、多知识点匹配。知识点不持久化，不提供账号、题库导入、批量文件处理或模型训练界面。
